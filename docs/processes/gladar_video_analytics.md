**Системы учета**

- IP-видеокамеры + облачный видеосервис — фиксируют видео и звук работы сотрудников точки (АЗС) и передают поток в облако. Данные хранятся на серверах в РФ с соблюдением 152-ФЗ, PCI DSS, GDPR, ISO. _TODO: уточнить название конкретного видеосервиса/платформы (в данных встречается интеграция с Ivideon — см. таблицы `ivideon_camera_offline_report*`)._
- ИИ-платформа Gladar — автоматически отбирает релевантные фрагменты видеопотока и выявляет признаки нарушений регламента для последующей проверки человеком.
- Аналитический центр Gladar (аналитики, ОКК) — верифицирует нарушения по согласованным с клиентом чек-листам.
- Личный кабинет Gladar — дашборды и отчёты, на основе которых менеджеры клиента принимают решения.
- Bitrix24 CRM — фиксация технических инцидентов (например, отключение камер, проблемы со звуком/связью) и постановка задач на устранение. _TODO: подтвердить — вывод сделан по косвенным данным (таблицы `b24Tasks`, `b24HGBTasks`, `b24PSSTasks` в текущем проекте), явно на сайте не упомянуто._

**Глоссарий**

- Точка / АЗС — объект клиента (автозаправочная станция сети-партнёра: Лукойл, Teboil и др.), на котором установлено оборудование Gladar.
- Оператор — сотрудник точки, работающий с клиентами на кассе (в данных — роль «Опер» в `TimeSlotType`).
- Заправщик — сотрудник точки, обслуживающий заправку топливом (роль «Запр» в `TimeSlotType`).
- Чек-лист — согласованный с клиентом перечень критериев регламента, по которым аналитик оценивает работу сотрудников точки.
- Аналитик — сотрудник аналитического центра Gladar, просматривающий отобранные ИИ фрагменты видео/аудио и фиксирующий нарушения/консультации по чек-листу.
- ОКК (отдел контроля качества) — сотрудник, повторно проверяющий работу аналитика; подтверждает нарушение либо аннулирует его (например, по причине ошибки аналитика или требования клиента).
- Рабочий / контрольный документ — тип проверки аналитика (значения `docType` = «рабочий» / «контрольный» в таблицах отчётов). _TODO: уточнить точное определение у клиента._
- Тайм-слот (`TimeSlotType`) — рабочая смена/должность сотрудника точки, за которую производится анализ (например, «ОперД» — оператор, дневная смена; «ЗапН» — заправщик, ночная смена). _TODO: подтвердить полную расшифровку кодов у клиента._
- Невозможка — случай, когда проанализировать тайм-слот невозможно по технической, аналитической причине или причине СРИМС (например: нет видеоархива, нет звука, камера отключена). См. таблицы `impossibility`, `ReasonTypes`.
- ТСС — статус занятости сотрудника аналитического центра (встречается в `Employees.Status`). _TODO: уточнить расшифровку аббревиатуры у клиента._
